# AI Advent Challenge · неделя 6 — локальная LLM

## День 26. Локальная модель запущена и отвечает

Модель **qwen3.5:4b** работает на этом компьютере через **Ollama**. Интерфейс задаёт ей
три вопроса разной сложности и показывает скорость генерации. Интернет для ответа не нужен.

### Машина и модель

| | |
|---|---|
| Процессор | AMD Ryzen 9 7940HS — 8 ядер, 16 потоков |
| Память | 64 ГБ DDR5-5600: 48 ГБ системе, 16 ГБ встроенной Radeon 780M |
| Движок | Ollama 0.35.1 — сервер `http://127.0.0.1:11434` |
| Модель | qwen3.5:4b — 4,2 млрд параметров, Q4_K_M, 3,3 ГБ |

### Установка и запуск

1. Ollama — установщик с [ollama.com/download](https://ollama.com/download): ставится без прав
   администратора и запускается вместе с Windows.
2. `ollama pull qwen3.5:4b`
3. `pip install -r requirements.txt`
4. `python -m app.main` → http://127.0.0.1:8000

### Как проверить задание

- **Модель работает локально** — `ollama ps` показывает `qwen3.5:4b  3.1 GB  100% CPU`,
  в шапке интерфейса — «в памяти · процессор».
- **CLI**: `ollama run qwen3.5:4b --think=false "Какая столица Японии? Ответь одним словом."`
- **HTTP API** (PowerShell):
  ```powershell
  (Invoke-RestMethod -NoProxy -Method Post http://127.0.0.1:11434/api/chat -ContentType 'application/json; charset=utf-8' -Body '{"model": "qwen3.5:4b", "messages": [{"role": "user", "content": "Какая столица Японии? Ответь одним словом."}], "think": false, "stream": false}').message.content
  ```
- **Три запроса разной сложности** — кнопка «Задать все три вопроса». Под каждым ответом —
  блок «Ресурсы, CLI и HTTP API»: сколько процессора и памяти потратил компьютер и какой
  запрос ушёл в Ollama.

В шапке — размер текста вопроса и ответа (выбор запоминается). Кнопка справа от ▶
разворачивает колонку на всю ширину: слева ответ, справа скорость и ресурсы. «очистить» убирает
ответ, вопрос остаётся. «?» под логотипом — мини-справка: что делает «думать» и остальные кнопки.

### Результат (05.10.2026, считает процессор)

| Запрос | Токенов | Время | Скорость |
|---|---|---|---|
| Простой — «Какая столица Японии? Ответь одним словом.» → «Токио» | 4 | 0,3–0,5 с | ~20 токенов/сек |
| Средний — «Что такое токен в языковой модели?…» | 76–97 | 5–7 с | ~15 токенов/сек |
| Сложный — задача про два поезда → «10:30» | 320–435 | 21–29 с | ~16 токенов/сек |

- Скорость почти одна и та же — ~15 токенов в секунду. Сложность меняет длину ответа, а с ней и время.
- Пока модель пишет, она занимает ~48 % процессора — 8 потоков из 16, по одному на физическое
  ядро; весь компьютер загружен на 80–90 %. Память модели — ~4,3 ГБ, видеокарта не используется.
- Задачу про поезда модель решила верно во всех 6 прогонах.
- Кнопка «думать» включает размышление: модель сначала рассуждает, потом отвечает. Тот же простой
  вопрос — 17–32 с вместо 0,5 с, задача про поезда — ~1 800 токенов и ~2 минуты.
- Первый вопрос после простоя дольше на 3–5 с: Ollama загружает модель в память. Без вопросов она
  выгружает модель через 5 минут.

**Встроенная видеокарта.** По умолчанию Ollama её не использует. С переменной
`OLLAMA_IGPU_ENABLE=1` модель целиком уходит на Radeon 780M через Vulkan. Генерация ускоряется
с 16 до 22 токенов/сек, но короткий вопрос обрабатывается дольше: ~1,4 с против 0,2 с.

### Как устроено

```
app/config.py      адрес Ollama, модель, порт — переменные OLLAMA_URL, MODEL, PORT
app/llm.py         клиент HTTP API Ollama: состояние, ответ потоком, счётчики токенов и времени
app/machine.py     что потратил компьютер за ответ: процессор и память (psutil)
app/main.py        FastAPI: страница, GET /api/status, POST /api/ask (поток строк JSON)
static/index.html  интерфейс
```

Ресурсы считаются двумя снимками — перед вопросом и после ответа: загрузка всего компьютера
за это время и время процессора, которое потратили сервер Ollama и его `llama-server` с моделью.

Без размышления вопрос уходит с параметрами, которые Qwen рекомендует для этого режима:
`temperature 0.7`, `top_p 0.8`. С размышлением — с настройками модели по умолчанию.
Формулы LaTeX из ответа модели интерфейс переводит в обычный текст.

## День 27. Локальная модель в Телеграм-боте

Бот в Телеграме отвечает моделью **qwen3.5:4b**, которая работает на этом компьютере. Телеграм
только передаёт сообщения: вопрос уходит в Ollama на `127.0.0.1:11434`, облачных моделей нет.

### Запуск

1. В Телеграме у **@BotFather**: `/newbot` → имя → username, оканчивающийся на `bot` → токен.
2. В корне проекта — файл `.env` со строкой `TELEGRAM_TOKEN=токен` (файл в `.gitignore`).
3. `pip install -r requirements.txt`
4. `python -m app.bot` → в консоли «Бот @… запущен», в Телеграме — боту `/start`.

### Что умеет

- **Ответ печатается на глазах** — черновиком (`sendRichMessageDraft`); ⏹ на черновике
  останавливает модель.
- **Markdown, таблицы и формулы** модели Телеграм рисует сам — сообщения `sendRichMessage`.
- **Фото** — qwen3.5 понимает картинки: фото чека и «Сколько всего заплатили?» → «570 ₽».
- **Память переписки** — 10 последних сообщений; «🆕 Новый диалог» её очищает.
- **«💭 Думать»** — модель сначала рассуждает: ход мысли виден, пока она думает, потом
  сворачивается в сообщение над ответом. Включённая кнопка — синяя.
- Под ответом — где он посчитан: `qwen3.5:4b · AMD Ryzen 9 7940HS · 16 токенов/сек · 6 с`.

### Как проверить, что облака нет

- В консоли бота на каждый вопрос — запрос к Ollama и итог:
  `→ POST http://127.0.0.1:11434/api/chat · qwen3.5:4b · 3 сообщения` и
  `← 96 токенов · 15,6 токенов/сек · 6,3 с`.
- `ollama ps` — модель в памяти этого компьютера.

### Результат (06.10.2026, считает процессор)

| Запрос | Время |
|---|---|
| «Какая столица Японии? Ответь одним словом.» | 0,5 с, после простоя — ещё 3 с на загрузку |
| Уточнение «А сколько там живёт людей?» — модель помнит, что речь о Токио | 0,8 с |
| Фото чека 800 × 600 — «Сколько всего заплатили?» | 6–9 с |
| Задача про поезда — ответ с формулами | ~24 с |
| «Сколько будет 17 × 23?» с «думать» | 19–28 с |
| ⏹ на длинном рассказе | Ollama освобождается сразу: следующий ответ — 0,5 с |

### Как устроено

```
app/bot.py      бот: getUpdates → модель → черновик → сообщение; Bot API — прямые HTTP-запросы (httpx)
app/llm.py      ask() принимает переписку — сообщения с фото, а не один вопрос
app/config.py   TELEGRAM_TOKEN — из .env
```

Фото уходит в модель самым крупным вариантом не больше 1000 px (обычно 800 px): это ~500
токенов и ~6 с обработки на процессоре. Модель видит только последнее фото переписки.

## День 28. Локальная LLM + RAG

RAG по правилам дорожного движения из недели 5 работает целиком на этом компьютере: поиск —
по индексу недели 5, ответ — локальная **qwen3.5:4b**. Для сравнения тот же промпт уходит
облачной **qwen3.8** (Alibaba Model Studio), которая отвечала в неделе 5.

### Как работает

```
вопрос → bge-m3 в Ollama → вектор вопроса
       → FAISS: 3 ближайших по смыслу из 274 фрагментов ПДД (индекс недели 5)
       → промпт «фрагменты + вопрос» → qwen3.5:4b на этом компьютере
                                     → qwen3.8 в облаке — для сравнения
```

- **Индекс — из недели 5, не пересобирался**: векторы читаются из FAISS, текст фрагментов — из
  SQLite, только на чтение.
- **Поиск — локально.** Вектор вопроса считает та же модель bge-m3, что строила индекс, но в
  Ollama, а не в Python: векторы совпадают до косинуса 0,998, и на 130 вопросах билетов нужный
  пункт попадает в первые три у 100 вопросов — ровно как у поиска недели 5. Поиск — ~0,2 с.
- **Схема проще, чем в неделе 5**: без переписывания вопроса, реранкера и порога — три ближайших
  фрагмента сразу уходят модели.
- **Промпт — как в неделе 5, один для обеих моделей**: коротко, прямой ответ первым, после
  утверждения — пункт в квадратных скобках, только по фрагментам; ответа в них нет — так и
  сказать. Облачная qwen3.8 думает перед ответом всегда — размышление ограничено 64 токенами,
  чтобы она, как и локальная, отвечала сразу.

### Запуск

1. `ollama pull bge-m3` — модель для поиска, 1,2 ГБ.
2. Индекс недели 5 лежит в соседней папке `../ai-advent-challenge-9-week-5/data/index`
   (собирается там: `python -m app.pipeline`); другой путь — переменная `INDEX_DIR`.
3. Для облака — `DASHSCOPE_API_KEY=ключ` в `.env`. Без ключа работает всё, кроме облачной колонки.
4. `pip install -r requirements.txt`, `python -m app.main` → http://127.0.0.1:8000/rag

### Экран

Одна страница, сверху вниз:

1. **Нашли в ПДД** — три фрагмента: пункт, раздел и сходство с вопросом; по клику — текст целиком.
2. **Ответ по этим фрагментам** — слева этот компьютер, справа облако: время, скорость, а у
   контрольного вопроса — ✓, если в ответе все ключевые факты. «Запрос» — куда и что ушло модели.
3. **Проверка** — итог по трём оценкам и строка на каждый вопрос: три прогона квадратами
   ✓ / ✗, по клику — сами ответы.

Контрольные вопросы — в списке ▾ в поле вопроса.

### Как проверить, что всё локально

- Под ответом «Запрос» — куда он ушёл: `127.0.0.1:11434` у локальной, `…aliyuncs.com` у облачной.
- `ollama ps` — в памяти этого компьютера обе модели: qwen3.5:4b и bge-m3, `100% CPU`.
- Кнопка «Облако» в шапке отключает облако: запрос туда больше не уходит, как без интернета.
  Локальная колонка отвечает как обычно, облачная — «Облако отключено». То же без сети (проверено
  с выключенным прокси): «Нет связи с облаком».

### Проверка: 10 вопросов × 3 прогона

Вопросы — 10 контрольных недели 5 (`control_questions.json`) с ожиданием и ключевыми фактами.
Ответ верный, если в нём есть все ключевые факты; факт — регулярное выражение по тексту ответа.

- **качество** — сколько ответов из 30 верные;
- **скорость** — сколько в среднем ждать ответа: от вопроса до последнего слова, вместе с поиском;
- **стабильность** — на скольких вопросах из 10 все три прогона дали один итог.

Модели отвечают одновременно, каждая — на один вопрос за раз; прогоны идут по кругу (1–10,
1–10, 1–10). Перед замером модели загружаются в память. Ответы — в `data/rag_check.json`;
остановленная проверка не затирает прежнюю. Верен ли ответ, считается при чтении: поправили
ожидание — итог пересчитывается без нового похода к моделям. Ожидания — как в неделе 5; к факту
«в Правилах этого нет» добавлено слово «отсутствует»: так отвечает локальная модель.

### Результат (08.10.2026, локальная модель — на процессоре)

| | Этот компьютер — qwen3.5:4b | Облако — qwen3.8 |
|---|---|---|
| **Качество** — верных ответов | 15 из 30 | **21 из 30** |
| **Скорость** — среднее время ответа, с поиском | 11 с (от 1,4 до 26 с) | **8 с** (от 6 до 11 с) |
| Генерация | 16 токенов/сек | 39 токенов/сек |
| **Стабильность** — вопросов с одним итогом в 3 прогонах | 8 из 10 | **10 из 10** |
| Сбоев | 0 | 0 |
| Без интернета | работает | «Нет связи с облаком» |
| Цена | бесплатно | ~1,2 тыс. токенов на ответ |

Проверка целиком — 5,5 минуты.

- **Обе верно** — простые факты и числа: жилая зона, знак аварийной остановки, протектор шин.
  На вопрос вне базы (штраф) обе отвечают, что в Правилах этого нет.
- **Облако сильнее на перечнях и деталях**: обгон — локальная всегда теряет «ближе 100 м перед
  переездом», знак «Начинающий водитель» — в двух прогонах из трёх теряет высоту знака 110 мм.
- **Обе ошибаются, где ответ собирается из нескольких условий**: ребёнок спереди — облако
  отвечает «с 12 лет», но пропускает «младше 7 — только в кресле»; самокат — пропускает «не
  тяжелее 35 кг».
- **Промах поиска, а не моделей** — «Можно ли ехать на красный свет?»: пункта 6.2 нет среди трёх
  фрагментов. Облако честно отвечает «ответа нет»; локальная в одном прогоне из трёх придумала
  исключение про спецтранспорт. В неделе 5 этот промах исправлял реранкер — здесь его нет ради
  простоты.
- **Нестабильна только локальная**: знак «Начинающий водитель» (✗ ✗ ✓) и права по QR-коду
  (✓ ✓ ✗). Облако на каждом вопросе отвечает одинаково от прогона к прогону.
- **Скорость локальной — это длина ответа и чтение промпта**: пишет 16 токенов/сек, а до первого
  слова 6–9 с читает ~1 000 токенов фрагментов (~120 токенов/сек на процессоре). Облако
  ровнее: 6–11 с на любой вопрос.

Проверка по ключевым фактам видит числа и слова, а не смысл, — поэтому под каждой строкой
таблицы на странице видны сами ответы.

### Как устроено

```
app/rag.py        поиск по индексу недели 5 и ответ модели — локальной или облачной
app/cloud.py      облачная модель (DashScope): тот же промпт, ответ потоком
app/check.py      проверка: 10 вопросов × 3 прогона — качество, скорость, стабильность
app/llm.py        + векторы для поиска: bge-m3 в Ollama, POST /api/embed
app/main.py       + страница /rag, POST /api/rag/ask (поток строк JSON), /api/rag/check
static/rag.html   страница RAG
control_questions.json   10 контрольных вопросов недели 5 с ключевыми фактами
```
